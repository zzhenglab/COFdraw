# COFdraw workspace

Open the Windows launcher, or open `/cofdraw.html` on the local COF Vision server. The interface uses the local chemistry engine; it needs no remote editor, model inference, or network fonts.

1. Search and select **Linkage chemistry**, then choose a starting combination or individual monomers. Dropdowns show abbreviations and full names; incompatible roles remain visible and disabled. **Monomer library** adds alias/full-name search and 2c/3c/4c/6c reactive-site filters. Select A, then inspect compatible B options and the reasons other choices are unavailable. Paste SMILES or use **Draw / edit** for other structures. **Update preview** shows reactive groups and site counts reported by the local chemistry engine.
2. Choose a compatible **connectivity template**. The controls check paired reactive-site requirements, including four-connected building blocks where the engine supports them. **Create drawing** prepares a connected finite chemical patch. Inspect its attachment ports in the layout controls. Unsupported linkage categories remain visible with their limitation; generation is disabled.
3. Select a drawing style or **Random style**. Styles are grouped into chemical, layered, and schematic presentations when available in the installed engine. Layered offsets do not predict crystal packing; cartoons simplify the depiction. The scope appears beside the canvas. The random seed is retained in the drawing audit and saved project; the chemical export remains separate from presentation.
4. Save PNG or SVG for presentation. MOL and SDF carry editable chemical graphs; CDXML is also offered when its writer and roundtrip checks succeed. If omitted, its reason appears below the export buttons. JSON carries the recipe and audit. **Save project** preserves both input monomers, the recipe, style, and layout choices for reopening.

**Adjust style** exposes the installed palette, font, continuation marks, substituent abbreviations, label size, bond weight, fill opacity, and transparent background. Layered styles also expose the number and opacity of illustrative layers. Press **Apply style** after making changes. Choosing a style card or **Reset defaults** clears overrides. A random style saves its resolved options as well as its seed, so changing image size or reopening a project preserves its appearance. Standard with no overrides uses the native stereo-capable renderer; custom presentation styles may reject assigned stereochemistry with an explicit message.

The monomer editor has single/double/triple bonds, benzene and five-/six-membered rings, element replacement, atom charge, movement, deletion, undo, and redo. Drag from an atom to add a bond; click an existing bond to apply the selected bond order. **Clean layout** asks the chemistry engine for new 2D coordinates. SMILES and single-molecule MOL import are alternatives to drawing.

The library's **Single-monomer editor** mode and **New monomer** open the editor without requiring a partner or framework. Save the edited MOL directly, or explicitly apply it to a building-block slot. All catalog monomers remain browsable, including those whose chemistry lacks an automatic framework transform. Site-count filters use reactive connection counts, not point-group labels: a C2-symmetric four-arm monomer remains 4c.

The scrollable monomer library shows individual chemical structure cards: three columns on ordinary desktop windows, five or six on wide screens, and one or two on mobile. Each card retains the full-name tooltip, reactive-site count, compatibility reason, and selection action. Click a structure or **Details** to expand its full metadata and editor action. Visible thumbnails are rendered by the local chemistry engine, with up to three concurrent requests and a session cache; off-screen structures load as you scroll. Filtering or changing the partner reuses those previews.

**Browse topology references** separates example reactive-site combinations, molecular symmetry, geometry, and periodic net codes. Reference-only 3D, cage, and multicomponent entries have no automatic-construction action. Where a related runtime template exists, it is still an explicit design choice in the main selector.

Assigned stereochemistry is retained on import and coordinate movement. Connectivity editing of such a monomer is blocked in this basic editor; use stereospecific SMILES or an external chemical editor. The editor does not assign new wedge, axial, or polymer stereochemistry. Structures are checked by RDKit before being applied.

Audited source recipes display their qualified COFex ID and full notation, alongside the monomers. Source annotations remain provisional (`ground_truth: false`). A chemistry or layout edit creates a designed variant without the source identity. Reopening a saved project also opens it as a design; reload the registered source separately to recover its verified provenance. Style-only changes retain the source record.

The templates are explicit design choices, not topology or synthesis predictions. Engine-generated design COFex notation and chosen topology are labeled separately from source identity; a `cat0` design assumption is not a source-confirmed catenation value. Edited/imported recipes do not inherit source identity. Outward ports remain open boundaries. These exports describe finite patches, not complete periodic unit cells or whole-COF SMILES. Reduced-linkage designs, where supported, describe the requested graph without asserting a direct synthesis from the displayed monomers.

The library is supplied by the local drawing API. Updated, verified source recipes and catalogs become available when the app loads them; the browser assets do not contain source PDFs or personal filesystem paths.

For local QA, `scripts/smoke_cofdraw_browser.py` exercises the real drawing API, editor, downloads, source identity handling, and responsive layout with an installed Chrome or Edge browser. It performs no model inference or training.

`node scripts/test_cofdraw_library.cjs` checks metadata filtering and paired template constraints without inferring chemistry from SMILES text. The browser smoke additionally exercises four-connected presets, unsupported linkage explanations, and layered/schematic styles when the installed API exposes them.

Use `--data-dir /path/to/cof-vision-data --output-dir /path/to/qa` to start an owned Python test server. To test a running Windows executable's local server instead, use `--base-url http://127.0.0.1:8765 --output-dir /path/to/qa`; this mode neither starts nor stops the app. The report records which server mode was exercised. An explicitly mocked final case checks the CDXML omission message separately from actual chemical exports.
